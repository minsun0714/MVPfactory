# 프론트엔드 기반 구현

2026-11-21 · API 독립 미리보기. 실제 프로젝트 실행이나 계정 연결 화면의 완성을 의미하지 않는다.

## 확인 경로

- `/office`: 왼쪽 세로 도구 모음, 아이소메트릭 사무실, 팀원 선택, 중앙 업무 팝업.
- `/design-system`: 색상·글꼴·버튼·입력·탭·배지·진행·빈 화면·팝업·알림을 조작하는 컴포넌트 도감.
- 실행: `npm run dev -- --port 3188`. 두 페이지는 DB·API 없이 열린다.

## 구현된 범위

- 아이보리·월넛·역할색, 픽셀 제목과 일반 본문, 넉넉한 간격, 최소 테두리.
- 공유 UI: `src/components/ui/`. props와 이벤트만 사용하는 버튼·필드·선택·탭·상태·팝업·아이콘.
- `useOfficePreview`가 팝업·역할별 임시 메모·프로젝트 이름·확대와 동작 줄이기 상태를 관리한다. 모두 현재 화면의 메모리 상태이며 새로고침하면 초기화한다.
- 모바일은 간단한 사무실과 팀원 목록, 전체 화면 팝업. 꾸미기는 PC 전용 안내를 제공한다.
- 팝업은 ESC·닫기·초점 순환·원래 초점 복원·배경 스크롤 잠금을 지원한다. 탭은 방향키·Home·End로 이동한다.
- SVG 사무실은 `public/assets/office/room.svg`다. 캐릭터 선택 버튼은 HTML로 제공한다. 정적 그림이며 회의 애니메이션은 아니다.

## 동시 작업 경계와 연결 지점

API·계약·서비스·기존 hook·루트 layout·package 파일은 이 작업에서 변경하지 않았다. 현재 브랜치에서 동시 작업하라는 사용자 지시를 따른다.

기존 루트 레이아웃의 헤더와 제한 폭은 `factory.css`에서 `.factory-ui`가 있는 경로에만 숨기고 초기화한다. 통합 단계에서 정식 route group 레이아웃으로 옮길 수 있다. `/`, `/new`, `/projects/[id]`의 기존 API 화면은 유지된다.

API 연결 시 `useOfficePreview`를 실제 업무 hook으로 교체하고 기존 `src/contracts`·서비스 계약을 따른다. 화면 상태를 서버의 실행·승인 상태로 취급하지 않는다. 역할별 상태·대화·산출물·공통 설정·프로젝트 목록을 실제 데이터로 연결해야 한다.

아직 구현하지 않은 범위:

- 실제 프로젝트 생성·저장·승인·계정 연결·실행 한도 저장
- 승인 요청 자동 팝업과 요청 대기열·재연결 처리
- 캐릭터 의상 조합, 사무실 편집·확장·저장
- 이동·착석·발언·해산을 실제 이벤트에 연결하는 회의 애니메이션

## 글꼴과 에셋

Galmuri 2.40.3 패키지의 Galmuri11을 로컬 WOFF2로 포함했다. 출처는 npm `galmuri`, 라이선스는 SIL OFL 1.1이다. 원문은 `public/fonts/galmuri/OFL.txt`에 보존한다. 실행 중 외부 글꼴 요청은 없다. 아이콘과 사무실은 저장소의 SVG 기반 도형이다.

## 검증

- TypeScript, 전체 ESLint, 프로덕션 빌드 통과.
- 브라우저 1440×1000 / 390×844에서 화면과 가로 넘침 확인.
- 팀원 팝업·탭 방향키·메모 유지·초점 순환·ESC·초점 복원 확인.
- 로컬 이름 변경·새로고침 초기화·API 요청 없음 확인.
- 모바일 전체 화면 팝업·PC 꾸미기 안내·동작 줄이기 확인.
- 도감 입력·팝업 확인 버튼·알림 닫기 확인.

실제 API와 DB 테스트를 실행한 결과는 아니며, 백엔드 완료 후 별도 통합 검증이 필요하다.
