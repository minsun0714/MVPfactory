# 사무실 API 연결 현황

2026-11-21 · `/office`에서 구현된 34개 HTTP 메서드를 모두 호출할 수 있다. `/office/preview`는 API 없는 시안이다. `/`는 사무실로, `/new`는 프로젝트 목록으로 이동한다. `/projects/:id`는 실행·결과 상세 페이지다. 기존 서비스 계약을 사용하는 화면은 더 이상 노출하지 않는다.

## 연결한 기능

| 화면      | API와 동작                                                                                  |
| --------- | ------------------------------------------------------------------------------------------- |
| 프로젝트  | 활성·보관 목록 전체 페이지, 상세, 생성, 보관·복원, 기획 범위 검사                           |
| 실행 관리 | 전체 실행 이력, 상세, 최초 실행·피드백 수정 실행, 일시정지·재개·같은 실행 재시도            |
| 결과      | 프로젝트 결과, 빌드·배포·제품 완료 구분, 앱·저장소·배포 링크, 마지막 정상 버전, 검증 보고서 |
| 작업      | 사용량·한도 상세, 전체 산출물 목록과 상세, 회의 이력과 상세                                 |
| 사무실    | office-state, 역할 상태·현재 단계·최신 소식·데모 여부                                       |
| 결정      | 열린 결정 목록·상세, 중앙 팝업, 제안 버전을 포함한 승인·수정 요청·예외 선택                 |
| 실시간    | 작업 공간·선택 실행 SSE, 순번 중복 제거, 15초 보완 조회                                     |
| 설정      | 공통 연결 상태, 공급자 연결 확인, 저장소 공개 범위·실행 한도 편집·저장, 서비스 상태         |

## 상태와 보호

- 실행과 프로젝트 생성은 별도 명령이다. REAL/DEMO를 명시적으로 선택한다. REAL 실패를 DEMO로 자동 전환하지 않는다.
- 생성·실행 제출 재시도에는 동일 입력의 Idempotency-Key를 재사용한다. 명령 중 중복 클릭과 팝업 닫기를 막는다.
- 보관은 외부 리소스를 삭제하지 않는다. 보관 프로젝트도 목록에서 선택해 복원할 수 있다.
- 꾸미기는 서버 버전으로 충돌을 감지한다. 실패 시 초안을 유지하고 사용자가 최신 상태를 다시 불러올 수 있다. 다른 팀원·배치의 미저장 편집은 개별 저장 시 유지한다.
- 비밀 키와 연결 대상은 `.env`에서 관리한다. 설정 API는 공개 범위와 한도만 변경한다.
- 목록·상세는 loading, empty, error와 재조회 경로를 제공한다. 프로젝트 변경 시 이전 데이터가 섞이지 않도록 요청을 취소한다.
- 모바일은 업무 조회·승인을 지원하고 꾸미기 편집은 PC에만 노출한다.

## 검증과 남은 범위

- 실제 로컬 API 조회와 브라우저 렌더링 확인.
- 서비스 테스트 10개 통과: 커서, 구조화 오류, 중복 방지 키, 결정 버전, 보관 목록, 실행 제어와 저장 요청, 회사 버전 충돌.
- 브라우저 모의 쓰기: 기획 범위 검사, 설정 저장·GitHub 연결 확인, 캐릭터·사무실 저장 요청, 충돌 후 초안 유지, 일시정지·재개·보관. 실제 DB 설정이나 프로젝트를 변경하지 않았다.
- 타입·린트 검사 및 `npm run build -- --webpack` 통과. Turbopack 권한 문제를 피하기 위해 이번 빌드는 webpack으로 검증했다.
- API 연결은 실제 AI·배포 구현 완료를 뜻하지 않는다. 현재 `createIntegrationReadiness().isRealModeAvailable()`는 false이며 REAL 실행을 거절한다.
- 메인 사무실은 PixiJS의 개별 레이어로 렌더링하며, 서버 회의 상태에 따라 참여자가 집결·복귀한다. 꾸미기 데이터 저장·좌표 미리보기와 메인 장면의 배치 반영은 아직 구분한다. 역할별 이벤트 패널은 최초 100개만 표시한다.
- 실제 쓰기 후 DB 복원, 워커를 통한 끝까지 실행, 외부 공급자 배포 통합 검증은 수행하지 않았다.

## 프로젝트 화면 분리

- `/projects`: 이름 검색, 사용 중·보관 목록, 12개씩 페이지 이동, 보관·복원. 새 프로젝트 폼은 버튼을 눌러 팝업으로 연다.
- `/projects/:id`: 선택한 프로젝트의 실행 제어·이력·산출물·최종 결과. 15초마다 상태를 갱신한다.
- `/office`: 팀과 사무실에 집중한다. 왼쪽 프로젝트 메뉴는 목록 페이지로, 실행·결과 링크는 선택 프로젝트 상세로 이동한다.
- 이전 `/office?panel=projects` 링크는 `/projects`로 이동한다. `/new`도 목록으로 이동한다.

## 로컬 출처 검사 수정

Next.js가 재구성한 내부 `request.url`의 호스트와 브라우저의 실제 호스트가 달라 정상 POST가 403이 되는 문제를 수정했다. 출처 검사는 요청의 `Host`와 프로토콜을 기준으로 하고, Host가 없는 직접 호출만 request.url로 대체한다. 임의 전달 헤더는 신뢰하지 않는다. 다른 출처·포트·프로토콜은 계속 차단한다.
실제 `http://127.0.0.1:3000` 브라우저에서 scope-check POST가 수정 전 403, 수정 후 200임을 확인했다. 외부 Origin은 수정 후에도 403이다. 이 검증은 DB에 프로젝트를 만들지 않는다.

## 실행 화면 UX 개선

Impeccable 4.10.0의 distill·Operate 지침을 적용했다. 스킬은 Codex 사용자 스킬 폴더에 설치했으며, 기존 DESIGN_SYSTEM.md와 UX_PRINCIPLES.md를 시각 기준으로 유지한다.

- 프로젝트 이름이 화면 제목이며, 실행 전에는 시작 영역 하나와 설정 펼침만 표시한다.
- 실행 방식·계정 설정 링크·범위 검사는 ‘실행 설정과 사전 확인’에 모았다. 보관은 ‘프로젝트 관리’에 둔다.
- 실행 중에는 서버 상태에 맞는 제어만 노출한다. 사용량·산출물·회의·검증 상세는 펼침 영역이다.
- 실행이 없거나 진행 중이며 정상 배포도 없다면 결과 영역을 표시하지 않는다. 결과의 내부 코드는 한국어 상태로 표현한다.
- 완료된 실행이 있고 최신 실행이 종료된 경우에만 수정 요청 폼을 노출한다.
- 실제 브라우저 화면과 모의 오류·완료 상태, 모바일 넘침, 설정 이동, 재시도 키 보존을 확인했다. 실제 실행·배포는 수행하지 않았다.

## PixiJS 사무실 렌더러

`/office`는 PixiJS 8.23.0을 지연 로딩한다. 기존 SVG를 18개 레이어로 분리하고, React hook → 읽기 전용 장면 모델 → PixiJS 렌더러로 책임을 나눴다. 회의 상세 API의 최근 발언을 텍스트와 역할 강조로 표시하며 서버에 없는 회의는 연출하지 않는다.

직접 캐릭터·원탁 클릭, 키보드 버튼, 동작 줄이기·건너뛰기, 화면 크기 변화, GPU 연결 상실 시 기본 그림과 재시도를 지원한다. 상태 전환 동안만 최대 30FPS로 갱신하고 나머지에는 ticker를 정지한다. 실제 프레임 시간·모바일 GPU 성능을 측정했다는 뜻은 아니다.

모델 테스트 4개와 기존 API 서비스 테스트 10개 통과. 실제 브라우저의 렌더링·클릭·페이지 왕복·복구, 모의 회의 입장·복귀·reduced-motion 캡처를 확인했다. 모션 리뷰에서 지적된 이름표 겹침은 배치 조정과 불투명 바탕으로 보완했다. 자세한 남은 에셋·배치 과제는 ANIMATION_SPEC.md §2를 따른다.

에셋 재생성: `python3 scripts/split-office-assets.py` 후 `npx prettier --write src/components/office/scene/assets.ts`. 원본 SVG 구조를 바꾸면 추출 인덱스·bounds.json·장면 좌표를 함께 갱신해야 한다.

## 프로젝트 상세와 작업 기록 분리

- `/projects/[id]`: 최신 결과와 시작·수정 요청 등 다음 행동을 표시한다. 진행 중인 실행은 사무실로 연결하고, 실패·정지 시 복구 제어를 유지한다.
- 수정 요청은 대화창에서 입력한다. 시작 요청 성공 후 해당 프로젝트의 `/office?project=[id]`로 이동한다.
- `/projects/[id]/history`: 실행 선택과 산출물·회의·검증·사용량 탭을 제공한다. 확정 기획도 이 페이지에서 확인한다.
- 공통 계정·공개 범위·한도는 기존 설정 화면에서 관리한다. 보관·복원은 프로젝트 목록에서 제공한다.
- 데모 결과에서는 빌드·배포·제품 검증의 미진행 지표를 숨기고, 실제 앱을 생성하지 않는 체험이라는 안내를 표시한다.

## 데모 신규 실행 종료

실행 방식 선택 UI를 제거하고 모든 신규 요청은 REAL로 보낸다. 실행 준비 상태를 `/api/runs/readiness`에서 확인하며, 준비되지 않았으면 이유와 함께 시작 버튼을 비활성화한다. 현재 실제 생성·배포 연동은 미구현이다. 과거 데모 기록은 사실대로 표시하며 재개·재시도는 지원하지 않는다. 전체 UX 검토는 [UI_UX_REVIEW.md](UI_UX_REVIEW.md)를 참고한다.
