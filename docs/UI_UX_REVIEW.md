# 서비스 UI/UX 검토

검토일: 2026-11-21. 대상: 현재 `/office`, `/projects`, 프로젝트 상세·작업 기록, 생성·설정·꾸미기·승인 대화창. 사용 스킬: Impeccable critique. **독립 에이전트 A(디자인)·B(기술/접근성) 검토 후 종합**했다. 두 에이전트의 브라우저는 프로필 잠금으로 실행되지 않았으며, 주 에이전트가 별도 탭에서 현재 설정·꾸미기·실행 준비 화면과 반응형 상태를 확인했다.

자동 detector는 엔진 캐시 디렉터리 권한 문제로 실행되지 않았다(exit 127). 따라서 자동 검사 통과나 오버레이 설치를 주장하지 않는다. 표준 critique-storage 도구도 같은 런처를 사용하므로 이 문서로 수동 저장했다. 비교 가능한 과거 점수 추이는 없다. 아래 목록은 확인 범위 내 문제이며, 미검증 상태까지 포함한 무결점 감사는 아니다.

## 총평

사무실은 픽셀 게임인데 업무 화면은 API 관리 양식에 가깝다. 핵심 문제는 색상보다 **행동의 결과가 눈에 보이지 않음, 맥락 누락, 편집값 유실, 내부 데이터 노출**이다. 아이보리·월넛, 픽셀 글꼴, 왼쪽 도구 모음, 4인 아이소메트릭 사무실은 유지한다. 파란색이나 일반 대시보드로 바꾸는 것이 해결책은 아니다.

독립 디자인 평가의 잠정 점수는 **24/40**이다. 시스템 상태 3, 현실 언어 2, 사용자 통제 2, 일관성 3, 오류 예방 2, 알아보기 쉬움 2, 효율 2, 간결성 3, 오류 복구 3, 도움말 2. 소스 중심 휴리스틱 평가이며 사용자 실험 점수는 아니다. 실제 실행 불가는 이 점수와 별개로 P0 제품 차단 문제다.

## P0 — 핵심 작업 차단

1. **실제 앱 생성·배포가 아직 불가능하다.** `readiness.ts`는 항상 false를 반환하고 워크플로우는 정적 데모 스크립트를 사용한다. 계정 키를 입력하는 것만으로 해결되지 않는다. 이번 변경으로 새 데모 접수·재개·재시도를 차단하고, 실행 준비 상태를 API에서 읽어 시작 버튼과 이유에 반영했다. 실제 공급자/샌드박스 연동 구현은 남아 있다. 근거: [readiness](../src/infrastructure/integrations/readiness.ts), [workflow](../src/application/workflow-steps.ts), [실행 유스케이스](../src/application/runs.ts). **코드·브라우저 확인.**

## P1 — 신뢰와 주요 행동

2. **꾸미기 저장이 실제 사무실에 반영되지 않는다.** 외형·가구·확장을 저장해도 렌더러는 고정 레이어를 사용한다. 저장 성공과 눈에 보이는 결과가 다르다. Company 상태와 렌더러를 연결하고 저장 전 실제 미리보기를 제공해야 한다. [OfficeEditors](../src/components/office/OfficeEditors.tsx), [renderer](../src/components/office/scene/renderer.ts). **코드 확인; 저장 요청 미실행.**
3. **다른 프로젝트의 승인임을 승인창에서 알기 어렵다.** 알림은 전체 프로젝트 결정을 모으지만 승인창에는 대상 프로젝트가 없고 배경은 기존 프로젝트다. 승인창에 프로젝트명·제안 버전·영향을 함께 표시해야 한다. [OfficeApiPanels](../src/components/office/OfficeApiPanels.tsx), [useOfficeWorkspace](../src/hooks/useOfficeWorkspace.ts). **코드 확인.**
4. **설정창을 닫으면 입력하던 값이 사라진다.** 모델 호출 횟수를 편집한 뒤 닫고 다시 열었을 때 저장 전 값이 없어지는 것을 재현했다. 꾸미기도 컴포넌트 내부 상태라 같은 위험이 있다. 초안 유지 또는 변경 폐기 확인이 필요하다. [useOfficeEditors](../src/hooks/useOfficeEditors.ts), [OfficeWorkspace](../src/components/office/OfficeWorkspace.tsx). **설정은 브라우저 재현, 꾸미기는 코드 확인.**
5. **‘연결 확인’이 다른 설정 초안까지 초기화한다.** 확인 후 전체 설정을 reload하면서 편집 컴포넌트가 해제된다. 연결 상태만 갱신하고 사용자가 편집한 공개 범위·한도는 보존해야 한다. [useOfficeEditors](../src/hooks/useOfficeEditors.ts), [OfficeEditors](../src/components/office/OfficeEditors.tsx). **코드 확인; 외부 연결 확인 요청은 실행하지 않음.**

## P2 — 흐름·정보 구조·조작

6. **가구 배치가 숫자 좌표 입력 작업이다.** 번호 점과 x/y/각도 입력만으로 가구 크기·방향·공간감을 판단하기 어렵다. 실제 가구 미리보기, 클릭·드래그와 키보드 이동, 선택한 가구만 편집하는 구조가 필요하다. [OfficeEditors](../src/components/office/OfficeEditors.tsx). **코드·화면 확인.**
7. **캐릭터를 꾸미면서 캐릭터를 볼 수 없다.** 머리·체형·옷을 텍스트로 선택하고 저장해야 한다. 팀원별 큰 미리보기와 즉시 반영되는 초안이 필요하다. 같은 파일. **코드·화면 확인.**
8. **설정과 꾸미기가 긴 대화창에 한꺼번에 쌓인다.** 계정 3개, 공개 범위, 한도, 서비스 상태가 한 스크롤에 있고 꾸미기는 캐릭터·확장·가구 전체가 이어진다. 과도한 간격까지 더해 저장·현재 편집 대상을 찾기 어렵다. 설정은 계정/실행 한도, 꾸미기는 캐릭터/공간 편집으로 분리한다. **현재 PC·700px 화면 확인.**
9. **내부 코드와 JSON이 제품 문구로 보인다.** `NOT_CONNECTED`, `PLANNER`, 원시 산출물 JSON은 사용자가 해석해야 한다. 한글 상태명, 역할명, 산출물 유형별 읽기 화면을 제공하고 원문은 보조 기능으로 둔다. [OfficeApiPanels](../src/components/office/OfficeApiPanels.tsx), [ProjectOperations](../src/components/office/ProjectOperations.tsx). **설정/꾸미기 화면·산출물 코드 확인.**
10. **연결 안내가 환경변수 이름에서 끝난다.** `.env` 사용은 이미 합의한 정책이지만 어디서 키를 발급하고 어떤 대상·권한을 넣어야 하는지 이어지는 도움말이 없다. 키는 계속 파일로 관리하되 공급자별 안내와 확인 실패 원인의 다음 행동을 연결한다. **코드·화면 확인.**
11. **비용 한도의 통화·집계 의미가 없다.** ‘예상 비용 한도’만으로 원/달러, 포함 범위, 0의 의미를 알기 어렵다. 통화·단위·0/빈값 규칙을 명시해야 한다. [OfficeEditors](../src/components/office/OfficeEditors.tsx). **코드 확인.**
12. **설정 입력 오류가 필드에 연결되지 않는다.** 숫자 입력의 min/step만으로 버튼 클릭 저장을 검증하지 못하고 서버 오류는 공통 메시지로 표시된다. 잘못된 입력칸 옆에 구체적 오류와 수정 방법이 필요하다. **코드 확인; 잘못된 설정 저장 미실행.**
13. **역할별 기록이 처음 100개 이벤트에 갇힌다.** 이후 실행 기록은 해당 역할에 있어도 보이지 않을 수 있다. 최신순 조회 또는 이어 불러오기가 필요하다. [OfficeApiPanels](../src/components/office/OfficeApiPanels.tsx). **코드 확인.**
14. **참여 방식의 결과를 예측할 수 없다.** ‘위임형/핵심 결정형/공동 설계형’이 어떤 상황에서 사용자를 멈춰 세우는지 설명이 없다. 선택한 방식의 승인 빈도·예외를 한 문장과 예시로 보여준다. [ProjectManager](../src/components/projects/ProjectManager.tsx). **코드 확인.**
15. **유효하지 않은 사무실 URL이 다른 프로젝트를 연다.** 지정된 ID가 없으면 첫 프로젝트로 조용히 대체되어 URL과 작업 대상이 어긋난다. 명시적 ID가 잘못된 경우 찾을 수 없음을 표시하고 목록으로 안내해야 한다. [useOfficeWorkspace](../src/hooks/useOfficeWorkspace.ts). **코드 확인.**
16. **설정 링크가 무관한 목록 요청 성공에 의존한다.** 프로젝트나 결정 목록이 실패하면 `?panel=settings` 처리가 실행되지 않는다. 복구하러 들어간 설정 화면이 열리지 않을 수 있다. URL에 따른 패널 열기를 목록 조회와 분리해야 한다. 같은 파일. **코드 확인.**
17. **차단 이유는 있지만 바로 해결할 경로가 부족하다.** ‘연결 확인’, ‘한도 도달’, ‘작업 서버 확인’이 나와도 해당 설정·상태로 이동하는 버튼이 없다. 상태별 해결 행동과 재개 조건을 붙여야 한다. [ProjectOperations](../src/components/office/ProjectOperations.tsx). **코드 확인.**
18. **앱 URL이 있으면 ‘완성된 앱’이라고 부른다.** 제품 검증이 미완료여도 링크 문구는 완성을 암시한다. 기본은 ‘앱 열기’, 완성 표현은 검증 완료 때만 사용해야 한다. [ExecutionResult](../src/components/office/ExecutionResult.tsx). **코드 확인.**
19. **641–767px에서 꾸미기 안내와 동작이 모순된다.** PC에서만 된다는 안내가 뜨지만 편집 폼도 같이 보인다. 모바일 전용 안내와 편집기 숨김의 기준이 다르다. 두 기준을 맞춰야 한다. [factory.css](../src/styles/factory.css). **700px에서 재현.** 모바일 꾸미기를 PC로 제한한 결정 자체는 기존 사용자 선택이므로 결함으로 세지 않는다.
20. **요청 중 닫기 버튼이 눌려도 반응하지 않는다.** pending일 때 닫기 함수를 무시하지만 버튼은 활성 상태다. 닫기 가능 여부를 명시하거나 창을 닫아도 작업 상태를 계속 볼 수 있게 해야 한다. [OfficeWorkspace](../src/components/office/OfficeWorkspace.tsx), [Dialog](../src/components/ui/Dialog.tsx). **코드 확인.**

## P3 — 정돈과 접근성 세부

21. **개발용 ‘UI 도감’이 주 제품 탐색에 상시 노출된다.** 실제 사용자의 작업과 분리해 도움말/개발 진입점으로 옮기는 편이 낫다. [OfficeWorkspace](../src/components/office/OfficeWorkspace.tsx). **화면 확인.**
22. **대화창 첫 포커스가 항상 닫기에 간다.** 긴 승인 내용이나 입력 화면에서는 제목 또는 첫 입력칸이 더 적절하다. 모달별 최초 포커스를 정해야 한다. [Dialog](../src/components/ui/Dialog.tsx). **코드·설정 화면 확인.**
23. **마지막 정상 배포가 날짜·SHA에 머문다.** 현재 실패와의 관계, 안전하게 열 수 있는 버전이 무엇인지 설명과 행동이 부족하다. [ExecutionResult](../src/components/office/ExecutionResult.tsx). **코드 확인.**

## 유지할 부분과 검증 한계

- 신규 프로젝트가 없는 화면의 큰 생성 버튼, 별도 작업 기록 페이지, 픽셀·월넛 정체성은 유지한다.
- 모달은 Escape/포커스 복귀·순환을 구현했다. 탭은 방향키/Home/End를 지원한다. 캔버스에도 키보드 대체 버튼이 있어 ‘접근성 전무’로 평가하지 않는다.
- 실제 기록과 데모 기록을 구분하는 과거 데이터 표시는 유지한다. 새 실행 선택지는 제거했다.
- 대비율·스크린리더·200% 확대·모든 네트워크 실패·실제 공급자 연동은 이번 검토에서 측정하지 않았다.
- 두 검토자가 같은 문제를 발견한 경우 하나로 합쳤다. 최근 제거된 확대 버튼·하단 업무 버튼, 이미 분리한 프로젝트 아코디언은 현재 결함으로 다시 세지 않았다.

## 권장 순서

1. 실제 실행 기반(P0), 저장한 꾸미기 반영, 승인 대상·초안 보존(P1).
2. 꾸미기 시각 편집 및 설정 화면 분리, 사용자 언어와 오류 복구(P2).
3. 기록 탐색·반응형 일관성·세부 포커스(P2/P3), 마지막으로 전체 화면 polish.

우선순위 선택 질문은 사용자 응답에서 진행한다. 이 문서는 수정 완료 보고서가 아닌 문제 목록이며, 데모 신규 실행 제거 외의 항목들은 후속 작업이다.
