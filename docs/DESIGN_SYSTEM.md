# 디자인 시스템

버전: 0.2 · 작성일: 2026-11-21  
적용 대상: UI를 구현하는 개발자와 코딩 에이전트.

스타일 방향은 **월넛 브라운과 선명한 포인트 색 + 라이트 우선 + 선명한 픽셀아트**다. 분위기와 문구는 [UX_PRINCIPLES.md](UX_PRINCIPLES.md), 애니메이션은 [ANIMATION_SPEC.md](ANIMATION_SPEC.md)를 따른다.

> 아래 10개 디자인 방향은 사용자 선택으로 확정했다. 구체적인 수치·서체·색상값은 구현과 접근성 검증을 거칠 제안이다. 문서 반영은 컴포넌트 구현 완료를 뜻하지 않는다.

## 시안 피드백 반영 — 2026-11-21

최신 형태 피드백: 그림책 같은 매끈한 곡선 대신 픽셀 윤곽과 단계별 명암을 강조한다. 캐릭터는 3px 단위의 계단형 윤곽으로 머리·몸의 볼륨을 표현하고 역할별 도구를 유지한다. 가구는 각진 디테일, 바닥은 픽셀 목재 질감을 사용한다. 검은 외곽선을 두껍게 추가하지 않고 색상별 명암으로 구분한다. 긴 글과 업무 패널의 글자는 선명하게 유지한다. 이전의 곡선형 캐릭터 우선 규칙은 이 피드백으로 대체한다.

최신 색상 피드백: 파란색 중심 팔레트를 사용하지 않는다. 사무실·가구·UI는 월넛·코코아 브라운과 밝은 중립색으로 구성한다. 캐릭터는 푸시아·번트 오렌지·바이올렛·에메랄드로 선명하게 구분한다. 픽셀 윤곽과 주변 색에 어울리는 경계를 유지하고, 진한 버튼 위 글자는 흰색으로 표시한다.

## 1. 원칙

1. **전체 픽셀 게임 UI, 긴 글은 가독성 우선.** 픽셀 감성은 캐릭터·사무실·버튼·입력창·탭·배지에 적용하고, 긴 본문과 폼은 읽기 쉬운 서체와 충분한 대비를 쓴다.
2. **토큰으로만 스타일링.** 색·간격·모서리·그림자를 컴포넌트에 직접 쓰지 않고 아래 토큰을 사용한다. 새 값이 필요하면 토큰을 먼저 추가한다.
3. **라이트 우선.** 라이트 테마를 기준으로 완성한다. 다크 테마는 이 버전의 범위가 아니며, 추가 시 토큰 값만 바꿔 대응할 수 있게 의미 기반 이름을 쓴다.
4. **상태를 모두 설계한다.** 모든 상호작용 컴포넌트는 default·hover·focus-visible·active·disabled·error(해당 시) 상태를 가진다.

## 2. 토큰 (Tailwind v4 `@theme` 기준)

프로젝트는 Tailwind CSS v4(`@import "tailwindcss"`)를 사용한다. 토큰은 `globals.css`의 `@theme` 또는 `:root` CSS 변수로 정의한다. 아래 이름은 목표 형태이며 아직 존재한다는 뜻이 아니다.

- 상태는 색 + 아이콘 + 텍스트 라벨을 함께 쓴다.

### 2.2 타이포그래피

| 용도                        | 서체(제안)                                       | 비고                                                           |
| --------------------------- | ------------------------------------------------ | -------------------------------------------------------------- |
| 제목·버튼·탭·짧은 배지 라벨 | Galmuri(갈무리) 또는 Neo둥근모 등 한글 픽셀 서체 | 라이선스(OFL 등)를 확인한 뒤 `next/font` 또는 self-host로 로드 |
| 본문·폼·긴 문장             | Pretendard 또는 시스템 sans-serif                | 가독성 우선                                                    |
| 코드·ID                     | 시스템 monospace                                 |                                                                |

| 토큰          | 크기 / 줄 간격 | 용도        |
| ------------- | -------------- | ----------- |
| `--text-xs`   | 12px / 1.5     | 보조 라벨   |
| `--text-sm`   | 14px / 1.6     | 보조 본문   |
| `--text-base` | 16px / 1.7     | 본문        |
| `--text-lg`   | 20px / 1.5     | 섹션 제목   |
| `--text-xl`   | 28px / 1.4     | 페이지 제목 |

- 픽셀 서체는 지정 크기의 정수 배수에서 가장 또렷하다. 임의의 소수 크기·`transform: scale`로 흐리게 만들지 않는다.
- 픽셀 서체로 두 줄 이상 길게 쓰지 않는다.

### 2.3 간격·모서리·그림자

- 간격: 4px 기반 스케일(`4, 8, 12, 16, 24, 32, 48, 64`). 임의 값 대신 스케일 사용.
- 모서리: 기본은 직각(`0`) 또는 `4px`. 픽셀 느낌을 위해 둥근 모서리를 크게 쓰지 않는다. 필요한 곳은 **계단형 모서리**(clip-path 또는 box-shadow 기법)로 표현한다.
- 테두리: 기본 `0`. 표면의 색 차이와 계단형 모서리로 구분하며 필요한 입력 경계만 1px 사용한다. 포커스 링과 오류 표시는 생략하지 않는다.
- 그림자: 기본 없음. 팝업처럼 겹치는 표면만 낮은 대비의 짧은 그림자를 선택 적용한다. 두꺼운 외곽선·강한 하드 섀도를 기본값으로 쓰지 않는다.
- 밀도 제안: 버튼·입력 높이 48px, 폼 간격 24px, 카드·팝업 안쪽 여백 24~32px. 작은 아이콘도 터치 영역은 최소 44×44px를 확보한다.

### 2.4 모션 토큰

| 토큰              | 값                           | 용도                   |
| ----------------- | ---------------------------- | ---------------------- |
| `--motion-fast`   | 120ms                        | hover·press            |
| `--motion-base`   | 200ms                        | 팝업 등장·닫힘         |
| `--motion-slow`   | 240ms                        | 예외적인 강조 전환     |
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 일반                   |
| `--ease-step`     | `steps(4, end)`              | 픽셀 스프라이트 프레임 |

`prefers-reduced-motion: reduce`에서는 위 시간을 0 또는 매우 짧게 하고 이동 효과를 제거한다.

## 3. 픽셀 렌더링 규칙

- 픽셀 이미지·스프라이트에는 `image-rendering: pixelated`를 적용한다.
- 스프라이트는 원본 크기의 **정수 배율**(2×, 3×, 4×)로만 표시한다.
- 캐릭터 기본 프레임은 32×32px, 가구·소품은 16px 격자를 기준으로 한다(제안). 사무실 배치 격자도 16px 단위를 따른다.
- 에셋은 PNG(투명 배경) 또는 SVG로 관리하고 `public/assets/` 아래에 종류별로 둔다(예: `characters/`, `office/`, `ui/`). 구조는 [ANIMATION_SPEC.md](ANIMATION_SPEC.md)의 스프라이트 규칙과 맞춘다.

### 승인 요청 표시와 입력 보호

- 새 승인 요청은 중앙 팝업으로 자동 표시한다. 동시에 여러 요청이 오면 한 번에 하나를 표시하고 나머지는 대기열·알림함에 둔다.
- 사용 중인 팝업의 미저장 입력을 지우거나 중첩 팝업을 띄우지 않는다. 편집 중에는 요청 도착을 알리고 현재 편집 종료 후 자동 표시한다.
- 사용자가 닫은 동일 요청은 갱신 때마다 반복해서 열지 않는다. 미응답 알림은 유지하며 직접 다시 열 수 있다. 새 제안 버전은 새 요청으로 다룬다.
- 자동 열린 팝업은 닫은 뒤 이전 초점으로 돌아간다. 팝업 등장이나 애니메이션 종료를 승인으로 간주하지 않는다.

### 4.2 확정된 시각 경험

사무실은 아이소메트릭 시점으로 표현한다. 데스크톱은 사무실을 크게 보여주고 캐릭터나 알림을 누르면 중앙 업무 팝업을 연다. 승인 요청은 자동으로 열린다. 팝업을 닫아도 CEO 응답 필요 여부와 진행 상태는 알림으로 확인할 수 있어야 한다. 회사와 캐릭터 외형은 모든 프로젝트에서 공유한다.

캐릭터·가구는 AI로 제작한 뒤 시점·스타일·크기·레이어·프레임 정합성을 보정한다. 아래의 격자·프레임 크기는 논리 배치와 제작 기준의 제안이며 아이소메트릭 화면의 투영 크기와 구분한다. 첫 버전에는 효과음·배경음이 없다.

## 5. 레이아웃

- 상단 헤더 없이 사무실을 넓게 표시한다. 왼쪽 세로 픽셀 도구 모음을 항상 표시하고 사무실과 팝업의 여백에 반영한다.
- 데스크톱 업무 화면은 오른쪽 패널 대신 중앙 팝업을 사용한다. 크기는 내용에 따라 조정하고 긴 본문은 팝업 안에서 스크롤한다.
- 중단점 제안: `sm 640 / md 768 / lg 1024 / xl 1280`. 모바일에서는 중앙 팝업을 전체 화면 대화창으로 전환한다.
- 모바일은 간단한 사무실·상태 요약·대화·산출물 확인·승인을 지원한다. 꾸미기와 공간 편집은 PC 전용으로 안내한다.
- 좁은 화면에서도 왼쪽 도구 모음은 작은 아이콘 형태로 유지하며 접근 가능한 이름과 선택 상태를 제공한다. 전체 화면 대화창이 열리면 작업에 집중하도록 그 위를 덮고 닫기·뒤로가기를 제공한다.
- 로그인은 구현하지 않는다. 공통 계정 설정을 프로젝트마다 반복 입력하지 않는다.

## 6. 구현 규칙 (코드 연결)

- 스타일은 Tailwind 유틸리티 + 위 토큰을 사용한다. 색 코드(`#...`)를 컴포넌트에 직접 쓰지 않는다.
- 재사용 UI(`Button`, `Badge`, `Card`, `Field`, `SpeechBubble` 등)는 `src/components/ui/`에 PascalCase 파일로 둔다. 업무 로직은 넣지 않고, 데이터와 콜백은 props로 받는다.
- 업무 상태와 명령은 custom hook이 제공한다. 표현 컴포넌트는 hook이 준 값을 그리기만 한다. ([AGENTS.md](../AGENTS.md) §4)
- 현재 `globals.css`는 요소 선택자(`button`, `h1` 등)에 직접 스타일을 지정한다. 이 시스템으로 이행할 때는 한 번에 전면 교체하지 말고 화면 단위로 단계적으로 옮긴다.
- 새 스타일 도입 후에는 라이트 테마, 모바일·데스크톱 폭, 키보드 포커스, 각 상태(loading·empty·error·CEO 대기)를 실제 화면으로 확인한다.

## 7. 확정이 필요한 항목

- 픽셀 서체 최종 선택과 라이선스 확인
- 최종 색상값(실제 화면과 대비 측정 후)
- 아이콘 세트(직접 제작 픽셀 아이콘 vs 외부 라이브러리)
- 로고·마스코트
