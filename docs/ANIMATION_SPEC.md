# 회의 애니메이션 명세

버전: 0.1 · 작성일: 2026-11-21  
관련 요구사항: REQ-015(캐릭터·사무실), REQ-016(회의 애니메이션), AC-010-3.  
함께 읽을 문서: [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md), [UX_PRINCIPLES.md](UX_PRINCIPLES.md).

> 이 문서의 길이·좌표·단계 값은 **제안 초안**이다. 실제 장면을 보며 조정하고 확정한 값을 이 문서에 반영한다.

**요약**

- 회의 장면은 소집 → 이동 → 착석 → 발언 → 반응 → 해산의 6단계다.
- 애니메이션은 서버의 실제 이벤트를 읽어서 재생만 한다. 재생이나 건너뛰기가 실행 상태를 바꾸지 않는다.
- 사무실 장면은 PixiJS로 렌더링한다. 동작 줄이기와 건너뛰기를 지원하며, 업무 패널·회의 요약은 React HTML로 제공한다.

## 1. 목적과 불변 규칙

회의 애니메이션은 팀의 실제 협업을 픽셀 사무실에서 보여 주는 연출이다.

1. **표현만 한다.** 애니메이션은 서버의 Run·Decision·작업 이벤트를 **읽어서 재생**한다. 재생·건너뛰기·종료가 실행 상태, 완료, 승인을 바꾸지 않는다. (AC-010-3, AC-016-4)
2. **없는 회의를 만들지 않는다.** 실제 작업 이벤트가 없으면 회의 장면을 시작하지 않는다. 대기·로딩을 회의로 위장하지 않는다. (AC-016-2)
3. **끝은 서버가 정한다.** 해산은 실제 결정·작업 종료와 일치할 때 재생한다. CEO 응답 대기·실패·중단은 장면에 반영하고 임의로 "완료"처럼 끝내지 않는다. (AC-016-3)
4. **텍스트로 대체 가능.** 건너뛰거나 동작을 줄여도 참여 역할, 발언 요약, 검토 주제, 결정 결과를 텍스트로 모두 확인할 수 있다. (AC-016-4)
5. **데모는 데모로.** 데모 실행의 회의에는 "데모" 표시를 유지한다.

## 2. 구현 방식 (PixiJS 전환)

| 항목       | 결정                                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------- |
| 렌더링     | PixiJS 8.23.0의 Application·Container·Sprite·Text. WebGL 우선                                           |
| React 경계 | custom hook이 비동기 초기화·요청 취소·정리를 맡고, 캔버스 렌더러는 API를 호출하지 않는다                |
| 에셋       | 승인된 SVG를 배경·책상·의자·캐릭터·원탁 18개 레이어로 분리. nearest 필터링                              |
| 이동       | 서버 office-state의 참여자만 900ms 보간 이동. 첫 진입·프로젝트 전환·동작 줄이기는 현재 좌표로 즉시 복원 |
| 성능       | 최대 30FPS, 이동·발언 강조가 끝나면 ticker 정지. 비활성 탭·화면 밖에서도 정지                           |
| 접근성     | 캔버스 외부에 키보드 업무·회의 버튼, 회의 주제·참여자·최근 발언 텍스트 제공                             |
| 복구       | 에셋·WebGL 실패 시 기존 SVG와 업무 버튼 유지, 렌더러 재시도 제공                                        |
| 수명       | 프로젝트 화면 이탈 시 renderer·texture·observer·ticker 해제. 서버 상태를 변경하지 않음                  |

PixiJS는 렌더링 엔진이다. 워크플로우 상태 기계, 이동 경로, 꾸미기 배치 규칙은 앱이 맡는다. Phaser는 게임 씬·물리 엔진까지 필요한 경우에 재검토하고, Konva는 도형 편집 중심 화면에 적합하다. 지금 범위에서는 React와 PixiJS의 책임 분리가 가장 작다.

### 구현된 범위와 후속 에셋

- 현재는 서버 스냅샷에 따른 집결·복귀, 최신 발언자 표시, 대기·일시정지 반영을 구현했다. 재접속 시 과거 회의를 처음부터 재생하지 않는다.
- 캐릭터는 기존 착석 그림을 재사용한다. 걷기·방향 전환·입 모양·고개 끄덕임용 스프라이트 프레임은 아직 없으며, 아래 6단계 전체 연출이 완성됐다는 뜻은 아니다.
- 현재 기본 배치의 좌표를 사용한다. 저장한 회사 배치·캐릭터 외형의 시각 반영, 임의 배치의 충돌 회피·경로 탐색은 후속 작업이다.
- `/office/preview`는 비교용 정적 시안으로 유지한다. 실제 `/office` 장면만 PixiJS를 사용한다.

참고: [PixiJS Application](https://pixijs.com/8.x/guides/components/application), [Scene Objects](https://pixijs.com/8.x/guides/components/scene-objects), [Events](https://pixijs.com/8.x/guides/components/events).

## 3. 데이터 계약

장면은 서버가 준 **회의 이벤트**로 구동한다. 이벤트의 실제 스키마는 API·DB 문서와 코드를 확인해 맞춘다. 아래는 장면이 필요로 하는 정보의 목록이다.

| 필요 정보                                   | 용도                           |
| ------------------------------------------- | ------------------------------ |
| 회의 ID, 연결된 Run·Decision ID             | 어떤 실제 작업의 회의인지 식별 |
| 참여 역할 목록                              | 이동·착석할 캐릭터 결정        |
| 주제                                        | 회의실 안내판·요약             |
| 발언 목록(역할, 요약 텍스트, 순서)          | 발언자 전환·말풍선             |
| 반응 정보(선택)                             | 참여자 반응(끄덕임, 갸웃 등)   |
| 회의 상태(진행, CEO 대기, 완료, 실패, 중단) | 장면 종료 방식 결정            |
| 결정 결과                                   | 해산 직전 요약 표시            |

- 말풍선 텍스트는 서버가 준 요약을 사용한다. 클라이언트가 발언 내용을 지어내지 않는다. 역할별 말투 연출이 필요하면 서버에서 생성·저장한 문구만 사용한다.
- 모델 출력 텍스트는 안전하게 렌더링(HTML 이스케이프)한다.

## 4. 장면 단계

회의는 아래 6단계로 구성한다. 시간은 제안값이며 `--motion-*` 토큰이 아닌 장면 전용 값이다.

| #   | 단계 | 내용                                                                                   | 길이(제안)                                         |
| --- | ---- | -------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 1   | 소집 | 회의실 문에 표시등 점등, 안내판에 주제 표시. 참여 캐릭터가 자리에서 일어남             | 600ms                                              |
| 2   | 이동 | 각 캐릭터가 책상에서 회의실로 걷기(4프레임 걷기 사이클). 역할 순서대로 100ms 간격 출발 | 1200~2000ms (거리에 비례, 속도 일정)               |
| 3   | 착석 | 지정 좌석으로 이동 후 앉는 프레임으로 전환                                             | 400ms                                              |
| 4   | 발언 | 발언자 전환. 발언자는 살짝 앞으로(−4px) + 말풍선 표시, 나머지는 경청 자세              | 발언당 1500~3000ms (텍스트 길이에 비례, 상한 있음) |
| 5   | 반응 | 발언 사이 짧은 반응(끄덕임, 느낌표, 물음표 아이콘 팝업)                                | 500ms                                              |
| 6   | 해산 | 결정 요약 카드 표시 후 캐릭터가 자리로 복귀. 표시등 소등                               | 800~1200ms                                         |

### 4.1 상태별 분기

| 서버 상태      | 장면 처리                                                                                                 |
| -------------- | --------------------------------------------------------------------------------------------------------- |
| 진행 중        | 4~5단계 반복. 새 발언 이벤트가 오면 이어서 재생                                                           |
| CEO 대기       | 발언을 멈추고 의자에 앉은 채 대기 자세. 대표 응답을 기다린다는 표시(경광등/손 든 아이콘). 해산하지 않는다 |
| 완료           | 결정 요약 → 6단계 해산                                                                                    |
| 실패           | 대기 자세에서 경고 아이콘 + 오류 요약. 임의로 해산·완료 표시 안 함                                        |
| 중단(일시정지) | 현재 프레임에서 정지(미세 idle만 유지). 재개 시 이어서 재생                                               |

### 4.2 이벤트가 밀렸을 때

- 재생 속도보다 이벤트가 빨리 쌓이면 **발언 길이를 줄여 따라잡고**, 이미 지난 발언은 건너뛰어 요약 목록에만 남긴다.
- 새로고침·재접속·늦게 진입한 사용자에게는 처음부터 재생하지 않고 **현재 상태에 맞는 장면 위치**(착석 + 최근 발언)나 **요약 보기**로 복원한다. 서버 상태가 유일한 기준이다.
- 같은 이벤트를 두 번 재생하지 않게 이벤트 ID(또는 순번)로 중복을 막는다.

## 5. 캐릭터 애니메이션 세트

| 동작                                  | 프레임(제안)                                | 비고               |
| ------------------------------------- | ------------------------------------------- | ------------------ |
| idle                                  | 2프레임, 800ms 루프                         | 미세 호흡          |
| walk                                  | 4프레임, 방향 4(상·하·좌·우) 또는 좌우 반전 | `steps(4)`         |
| sit                                   | 1~2프레임                                   |                    |
| talk                                  | 2프레임, 입 움직임                          | 발언 중            |
| react-nod / react-think / react-alert | 각 2~3프레임                                | 아이콘 팝업과 함께 |
| wait                                  | 2프레임                                     | CEO 대기           |

- 기본 프레임 32×32px, 표시는 정수 배율. 스프라이트 시트 한 장에 동작별 행을 둔다.
- **꾸미기 레이어:** 몸·헤어·의상·액세서리를 별도 레이어로 합성해 같은 프레임 타이밍을 공유한다. 레이어마다 동일한 프레임 수·크기를 지킨다. (AC-015-1)
- 역할색(`--role-*`)은 이름표·말풍선 칩·좌석 표시에 쓰고, 꾸미기와 무관하게 역할을 식별하게 한다. (AC-015-4)

### 5.1 에셋과 공유 설정

캐릭터·가구는 AI로 생성하고 아이소메트릭 시점·크기·꾸미기 레이어·동작 프레임을 보정한다. 모든 프로젝트가 하나의 회사와 캐릭터 설정을 공유한다. 제공 아이템과 공간 확장은 활동 해금 없이 처음부터 사용 가능하다. 첫 버전의 연출은 무음이며 효과음·배경음을 포함하지 않는다.

## 6. 사무실·회의실 공간

- 격자: 16px 타일. 책상·의자·장식은 격자에 맞춰 배치한다.
- 팀은 PM·기획자·디자이너·개발자 4명으로 고정하며 최대 4명이 회의에 참여한다. 기본 회의 공간은 4명 수용을 기준으로 설계한다.
- 이동 경로는 단순한 직각 경로(타일 기반)로 시작한다. 충돌 회피가 필요하면 출발 간격과 경유점으로 해결하고, 복잡한 경로 탐색은 필요가 확인될 때 도입한다.
- 사용자가 배치를 바꾸면 좌석·경로 정보가 즉시 갱신되고 저장·복원된다. (AC-015-2, AC-015-3)

## 7. 제어와 접근성

### 7.1 사용자 제어

- 장면에는 항상 **건너뛰기**(요약으로 이동)와 **다시 보기** 버튼이 있다.
- 재생 속도 옵션(1×, 2×)은 선택 기능으로 검토한다.
- 건너뛰어도 서버 상태와 이후 흐름(결정 응답, 재개)은 동일하다.

### 7.2 동작 줄이기 (`prefers-reduced-motion: reduce`)

- 걷기·이동·반응 팝업을 제거하고 **즉시 위치 전환**(착석 상태)으로 표시한다.
- 발언은 말풍선 교체만 하고 이동·흔들림은 없다. 점멸하는 표시등은 정적 표시로 바꾼다.
- 정보량은 줄이지 않는다. 요약 목록은 항상 보인다.

### 7.3 스크린 리더·키보드

- 장면 컨테이너에는 역할과 텍스트 설명을 제공하고, 캐릭터 이미지는 장식이면 `aria-hidden`으로 둔다.
- 발언·상태 변화는 `aria-live="polite"` 영역에 텍스트로 전달한다(과도한 낭독을 막기 위해 요약 단위로).
- 건너뛰기·다시 보기·결정 응답 버튼은 키보드로 접근 가능하고, 포커스가 장면 애니메이션에 가려지지 않는다.
- 초당 3회를 넘는 점멸을 사용하지 않는다.

## 8. 성능 기준

- 애니메이션은 `transform`과 `opacity` 위주로 구성한다.
- 화면 밖이거나 탭이 비활성일 때는 재생을 멈추고 복귀 시 현재 상태로 맞춘다.
- 스프라이트는 시트로 묶어 요청 수를 줄이고, 중저사양 기기에서 끊김이 없는지 확인한다.
- 최대 4명의 캐릭터가 동시에 이동할 때 CPU 사용과 프레임 안정성을 확인한다.

## 9. 구현 체크리스트

- [ ] 장면 재생 로직이 custom hook에 있고 컴포넌트는 표현만 한다
- [ ] 이벤트 중복 재생 방지, 늦은 진입·새로고침 복원이 동작한다
- [ ] CEO 대기·실패·중단 상태가 장면에 반영되고 임의 완료가 없다
- [ ] 건너뛰기, 다시 보기, 동작 줄이기에서도 요약·결정 내용을 볼 수 있다
- [ ] 애니메이션 유무와 관계없이 Run·Decision 상태가 같다
- [ ] 데모 회의에 "데모" 표시가 있다
- [ ] 모바일 폭에서 장면 또는 요약 대체 보기가 동작한다
- [ ] 캐릭터 꾸미기 변경 후에도 역할 식별과 진행 확인이 가능하다

## 10. 확정이 필요한 항목

- 아이소메트릭 좌석·이동 경로의 최종 시각 배치
- 회의 이벤트의 실제 API·DB 스키마(기존 구현 확인 후 연결)
- 효과음·배경음은 첫 버전에서 제외(확정). 소리로만 전달하는 정보는 두지 않는다.
- 제작 방식은 AI 생성 후 보정으로 확정. 사용 도구·소재의 이용 조건과 최종 에셋 품질은 제작 시 확인한다.

## 공통 UI 모션 — 사용자 선택 반영 (2026-11-21)

버튼은 짧고 또렷한 눌림, 중앙 업무 팝업은 빠른 등장·닫힘을 사용한다. 튕김이나 긴 연출로 조작을 지연하지 않는다. 기본 제안은 버튼 120ms, 팝업 200ms이며 DESIGN_SYSTEM의 모션 토큰을 따른다. 소리는 넣지 않는다. 모바일 전체 화면 대화창에도 같은 원칙을 적용한다. reduced-motion에서는 이동 효과를 제거한다. 승인 팝업은 실제 요청 이벤트로 열며 회의 애니메이션 종료를 기다리지 않는다.
