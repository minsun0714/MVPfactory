## 목적

파일 항목 누락과 배열 형식 오류까지 개수 오류로 표시하던 문제를 구분한다.
개발자 프롬프트에 JSON 예시와 1~60개 제한을 명시하고, 형식 재요청에서
이전 소스를 4,000자로 잘라 보내지 않는다. 수정 입력과 같은 영문
files/path/content도 동일한 검증을 거쳐 받아들이되 충돌 키는 거부한다.

## 완료 조건

- 생성·수정에서 한국어·영어 키를 동일한 내부 파일 계약으로 변환한다.
- 누락·형식·개수 오류를 구분하고 중복 경로·잘못된 내용은 계속 거부한다.
- 긴 응답의 형식 복구와 최대 한 번 재요청을 회귀 테스트한다.
- 실제 실패 응답과 실제 모델 재실행은 별도 미검증으로 보고한다.

## 검증 방법

에이전트 회귀 테스트, 관련 모델·소스 테스트, 타입 검사·lint·빌드.

## 검증 결과

- 변경 전 에이전트 테스트 7개 통과.
- 변경 후 에이전트·OpenAI 어댑터·사용량·소스 정책 테스트 26개 통과.
- 타입 검사와 프로덕션 빌드 통과. Lint 오류 없음(기존 docker-sandbox.ts 경고 1개).
- 전체 서식 검사는 수정하지 않은 tasks/done/remove-unused-pages.md에서 실패.
- 실제 실패 응답을 확보하지 못해 발생 원인은 미확정. 유료 모델 재호출과
  실행 재시도는 수행하지 않음. 기존 워커를 재시작해야 변경이 적용됨.
